R&R Design · Дуэт R3. Воспроизводимый контроль конечных STL

Сравнение расположено в подпапках R2 и R3. В каждой wall-summary.json содержит суммы, координаты характерных случаев и SHA-256 проверенного STL, stations.json — каждый локальный замер. В двух CSV.GZ записан каждый луч с номером входной и выходной граней, исходной позицией, направлением, выходной точкой и длиной хорды в миллиметрах. Архивы открываются через 7-Zip или Python gzip. Идентификатор грани — порядковый номер 50-байтовой записи бинарного STL, начиная с нуля. CSV-поле exitFace0 = −1 показывает отсутствие выхода.

Повторный запуск. Из корня распакованного комплекта с White.stl и Champagne.stl, в Windows PowerShell. Нужен Python 3.12 с 64-битной архитектурой.

  py -3.12 -m venv .audit-venv
  .\.audit-venv\Scripts\python.exe -m pip install -r audit/requirements.txt
  .\.audit-venv\Scripts\python.exe audit/walls.py . audit/my-run
  .\.audit-venv\Scripts\python.exe audit/stations.py . audit/my-run

Для другого экспорта заменить точку в двух последних командах на папку с его файлами White.stl и Champagne.stl. Ожидается один замкнутый ориентированный компонент в каждом STL. walls.py работает в системе мм. Вынесенные локальные станции относятся к этому кольцу, с общим началом координат для металлов и камней; stations.py дополнительно читает assembly.json. Начальные и конечные точки печатаются в координатах готовой модели.

Определение луча. Используются геометрические нормали треугольников. Начало в центре каждой грани. На пути длиной до 50 мм по внутренней нормали первые 0,0000001 мм пропускаются, чтобы исключить стартовую поверхность. Принимается первая другая грань на положительном расстоянии больше этого допуска. Учитываются все хорды строго короче 0,45 мм. Не нашедшие выхода лучи сохраняются отдельным классом. У близких к рёбрам и касательных лучей результат чувствителен к округлению координат; алгоритм не удаляет такие результаты из общей суммы.

Выход считается встречным при exitCos ≥ 0,5, то есть угол между направлением луча и внешней нормалью выходной грани до 60°. Короткая хорда помечается nearCreaseIfThin, если одна из её точек находится ближе 0,075 мм к ребру с двугранным углом более 30°. Старты по центрам треугольников означают, что числа относятся к данной триангуляции. Самое малое число среди лучей не равно минимальной несущей стенке.

Проверка траекторий и посадок. В рабочей копии комплекта можно запустить:
  .\.audit-venv\Scripts\python.exe audit/check.py .
Сценарий читает оба металла, 7 файлов stones, assembly.json и Assembly.glb и записывает свой qa.json в рабочую копию. Проверяются полные пути, высоты каждого конца от верхнего рундиста, сечения и стык. Выпущенный комплект содержит объединённый протокол, куда дополнительно сведены результаты walls.py, stations.py и CGAL.

Проверка самопересечений доступна отдельно в self_intersections.py. В контрольном окружении использована сборка CGAL 6.0.1.post202410241521. Установить её в то же окружение и запустить:
  .\.audit-venv\Scripts\python.exe -m pip install cgal==6.0.1.post202410241521
  .\.audit-venv\Scripts\python.exe audit/self_intersections.py . audit/my-run/intersections.json --require-clean

Значения зазоров относятся к идеальным жёстким телам в цифровой сборке. Слой поддержки и усадка отливки, шлифовка, деформация при закрепке и зазор реального инструмента подлежат проверке на образце.
